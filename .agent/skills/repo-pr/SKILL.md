# GitHub PR 마무리

1. 요청이 PR 생성인지 초안 작성인지 구분합니다. “PR 만들어줘”와 같은 명시적인 생성 요청은 해당 PR 게시 승인으로 처리합니다.
2. 대상 브랜치, 커밋, 변경 경로와 연결할 GitHub Issue를 확인합니다. 브랜치 번호와 Issue 번호를 대조하고, 같은 작업의 열린 PR이 있으면 그 링크를 사용합니다. Issue가 필요한 경우 루트 [작업 규칙](../../../AGENTS.md)의 사전 승인 절차를 따릅니다.
3. 구현과 변경 범위에 필요한 검증을 마칩니다. 필요한 검증이 실패했거나 실행이 막혔다면 원인을 해결하거나 미완료 상태를 보고하고 PR 생성을 보류합니다.
4. [기여 가이드](../../../CONTRIBUTING.md)와 [PR 템플릿](../../../.github/pull_request_template.md)으로 제목과 본문을 작성합니다. 제목과 본문에 같은 Issue 번호를 적고, 본문에 `Closes #번호`를 사용합니다. 실제 검증 결과와 확인하지 못한 항목을 구분하고, 공통 설정 합의 체크는 실제 합의가 확인됐을 때만 표시합니다.
5. 초안 요청이면 제목과 본문을 전달합니다. 생성 요청이면 공통 설정 합의 등 저장소의 사전 조건을 확인한 뒤 이번 작업만 커밋하고 작업 브랜치를 올립니다. main을 대상으로 PR 하나를 생성하고 링크를 전달합니다. 병합은 별도 요청과 저장소의 리뷰 절차를 따릅니다.
