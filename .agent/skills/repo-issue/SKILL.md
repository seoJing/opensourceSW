# GitHub Issue 시작

1. 루트 [작업 규칙](../../../AGENTS.md)에 따라 사용자가 이번 Issue의 생성과 범위를 승인했는지 확인합니다. 승인 뒤 목적이나 범위가 달라지면 변경한 제안을 다시 확인받습니다.
2. [Issue 양식](../../../.github/ISSUE_TEMPLATE/task.yml)과 [기여 가이드](../../../CONTRIBUTING.md)를 읽습니다. 승인된 제목과 완료 조건, 담당자와 수정 경로, 공통 설정·API 계약·병합 순서, 검증 방법을 Issue에 정리합니다. 확인되지 않은 담당자나 팀 합의는 미정으로 표시합니다.
3. 대상 저장소와 열린 Issue를 확인합니다. 같은 작업이 이미 등록돼 있으면 링크를 알려주고 기존 번호를 사용합니다. 새 작업이면 GitHub에 Issue를 만들고 반환된 번호와 링크를 확인합니다. 생성 결과가 불명확하면 같은 Issue가 생겼는지 확인한 뒤 재시도 여부를 결정합니다.
4. 구현도 요청받았다면 그 번호로 최신 main에서 작업 브랜치를 만들고 작업을 시작합니다. Issue 생성만 요청받았다면 링크와 번호를 전달합니다.
